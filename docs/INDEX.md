# Documentation index

This is the contributor-facing index for `docs/`. It is intentionally thin:
canonical, user-facing documentation lives on the website, not here. A topic
lives in exactly one place - if it has a website page, it is not duplicated in
this tree.

## Canonical user documentation: the website

**File:** [../website/](../website/)

Tutorials, how-to guides, reference, and explanation (architecture, data flow,
security model, scoring, policies) live in `website/docs/`, organized with the
Diataxis framework. Run it locally:

```bash
cd website
npm install   # first run only
npm start     # local dev server with hot reload
npm run build # static production build
```

## What stays in this tree

Everything below has no website equivalent, either because it is generated,
gitignored, or specific to contributors rather than end users of the product.

| Path | What it is |
|---|---|
| [reference/env-vars.md](reference/env-vars.md) | The full environment-variable catalogue. Generated by `scripts/check_env.py --docs`; do not hand-edit. `make env-check` gates drift in CI. |
| [trust-gate/](trust-gate/) | Trust Gate deep-dive guides (`README.md`, `explained-simply.md`, `how-it-works.md`, `data-quality-process.md`, `architecture.md`, `complete-guide.md`, `references.md`). The website carries only one Trust Gate how-to page; this set has no site equivalent. |
| [quality-evaluation-methodology.md](quality-evaluation-methodology.md) | The Trust Gate's data-quality measurement methodology: the framework, algorithms, and decision logic behind the checks. No site equivalent. |
| [superpowers/](superpowers/) | Specs and plans for in-progress and completed repository work. |

## Not tracked by git

`docs/internal/` is excluded via `.gitignore`. It holds planning documents,
architecture reviews, and the file-by-file module map, none of which are
intended for public distribution. It exists only in local working trees; see
`internal/INDEX.md` there for its own index if present.
