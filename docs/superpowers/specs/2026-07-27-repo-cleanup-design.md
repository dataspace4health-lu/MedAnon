# Repo cleanup design

Date: 2026-07-27
Branch: `Refactor`
Status: approved, pending implementation plan

## Problem

The repository has accumulated three kinds of drift that make it hard for a new
engineer to trust what they read:

1. Documentation is maintained twice, in `docs/` and in the `website/`
   Docusaurus site, with no mechanism keeping the two consistent.
2. Documentation content predates the current branch. Every public doc was last
   modified by a cosmetic commit on 2026-07-14, while the `Refactor` branch has
   since extracted `packages/medanon-core`, deleted four config profiles, and
   moved the Trust Gate guides into `docs/trust-gate/`.
3. The live `.env` has grown to 208 keys with no curation pass, and the
   security posture it expresses is partly implicit.

The repository does **not** have a dead-code problem. That was measured, not
assumed, and the measurements are recorded below so the plan does not spend
effort where there is nothing to find.

## Governing principle

Every claim this cleanup makes, in a doc or in a commit message, must be
traceable to a command that verifies it. Where a claim is countable, a script
must count it. Where a claim is prose, a human must read it against the code.
No number is copied forward from an older document without re-deriving it.

This principle comes from evidence inside the repository. Of every documentation
surface here, exactly one did not rot: the environment-variable catalogue. It is
also the only one with a CI-gated drift check, `scripts/check_env.py` feeding
`docs/reference/env-vars.md`, enforced by `git diff --exit-code` in
`.github/workflows/ci.yml`. Same authors, same period, same delivery pressure.
The difference is mechanical enforcement, so the plan extends that mechanism
rather than relying on discipline.

### Deliberately out of scope

The following were investigated and found not to be problems. They are recorded
so the work is not repeated.

- Dead code. All docs are linked, `INDEX.md` has no broken links, and exactly
  one client page is unreferenced (`ResetPasswordPage`, which belongs to the
  quarantined `client/.wip-auth/` work).

  local-only. This was raised and the owner decided to keep the exclusions, so
  the cleanup targets the working tree.

## Decisions taken

| Question | Decision |
|---|---|
| Audience for the cleanup | The working tree, not a fresh clone. Gitignore policy is unchanged. |
| Canonical documentation | `website/` is canonical. `docs/` shrinks to the contributor and operator layer with no site equivalent. |
| Relationship to in-flight work | Land the `Refactor` branch first, from a clean tree, before cleanup begins. |
| Env reference | The live `.env` is the source of truth for what a real deployment sets. |

## Phases

Each phase is independently committable and ends at a gate. Work stops at any
gate that does not pass. The repository is in a better state than it started
after every completed phase.

### Phase 0. Land the Refactor branch

Commit the existing 126-file working set as scoped commits, one concern per
commit: the `medanon-core` extraction, the Trust Gate documentation move, the
config profile deletion, and the client changes. Commits require explicit
authorisation before they are made.

Gate: `make ci-local` passes, covering ruff, both import-linter contracts, env
drift, medanon-core tests, NLP entity sync, the anonymizer suite and the Trust
Gate suite.

### Phase 1. Hygiene

Delete `.env.bak.1783666157` and `scripts/__pycache__`. Triage each of the nine
untracked paths (`bench/`, `docker-compose.bench.yml`,
`docker-compose.override.yml`, `docs/overview.md`, `docs/superpowers/`,
`monitoring/rules/`, `output`, `services/gpas/config/`,
`services/gpas/sqls_pg/03_init_gpas_domain.sql`) to one of three outcomes:
track it, add it to `.gitignore`, or delete it.

Gate: every untracked path has a recorded verdict, and `git status` shows
nothing unexplained.

### Phase 2. Documentation topology

Produce a page-level ownership matrix covering all 25 public `docs/` files and
all 38 `website/docs/` pages. Assign every topic exactly one home. `website/`
takes users and evaluators. `docs/` retains only what has no site equivalent:
the architecture, component and data-flow references, the generated env
catalogue, and `internal/`. Delete the overlap and repoint the documentation
table at `README.md:240-249`.

Gate: the link checker reports zero broken links, and `cd website && npm run
build` succeeds with an unchanged page count.

### Phase 3. Drift guard

Add `scripts/check_docs.py`, modelled on `check_env.py`, checking only
mechanical facts:

- counted claims in prose against the tree, such as the number of config
  profiles, compose services and profiles
- every repository path referenced in a document exists
- every internal document link resolves

Prose correctness is explicitly out of scope for the tool. Wire it into
`.github/workflows/ci.yml` and `make ci-local`.

This phase precedes the accuracy rewrite deliberately. Running the guard against
the un-rewritten tree enumerates the countable drift, and that failure list
becomes the starting work queue for Phase 4 instead of being assembled by hand.

Gate: the script runs, its failure list is captured as the Phase 4 queue, and it
fails when a counted claim is deliberately broken in a scratch edit.

### Phase 4. Documentation accuracy

Rewrite the surviving documents against the post-`Refactor` tree. The Phase 3
failure list and the drift table above are the starting queue, not the complete
list; each surviving document is read in full against the code it describes.

The unresolved AUTH.2 finding, that nginx performs no authentication and
`/fhir/*` serves identified data including an SSN identifier, stays documented
in `docs/security.md`. It is an open risk accepted by the owner, and removing it
during a cleanup would be the worst available outcome.

Gate: `scripts/check_docs.py` passes on the rewritten tree, plus a human read of
each rewritten file.

### Phase 5. Environment

Using the live `.env` as reference: delete the 7 dead keys; declare all 11
posture flags explicitly at their current effective values so the security
posture is reviewable in the file operators actually edit rather than inherited
from `docker-compose.yml`; and group the 155 remaining overrides into labelled
sections mirroring `docs/reference/env-vars.md`. Add any posture flag missing
from `.env.example`. No secret values are copied into documentation.

Gate: `python3 scripts/check_env.py --env .env` reports 0 dead keys and 0 unset
posture flags, and `python3 scripts/check_env.py` still passes clean.

### Phase 6. CLAUDE.md and Claude memory

Verify every claim in the 240 lines of `CLAUDE.md`, starting with the config
profile count, and keep it an orientation layer rather than a catalogue.

Consolidate the 56 memory files. Clusters suitable for merging include three
bulk-export files, three gPAS operational gotchas, four Trust Gate files, and
six performance and benchmark files. Memories describing work that has landed or
findings since fixed are deleted rather than merged.

Gate: `MEMORY.md` matches the files on disk exactly, and no retained memory
asserts a `file:line` that no longer resolves.

## Risks

The largest risk is Phase 4 replacing stale but true text with fresh and wrong
text. A document that confidently misstates which privacy barrier fails closed
is more dangerous than one that is visibly dated. This is mitigated by reading
each document against the code rather than against its predecessor, and by the
Phase 3 guard catching the countable subset automatically.

The second risk is scope growth in Phase 2. The ownership matrix is a decision
record, not an invitation to restructure the site. Pages move or are deleted;
they are not redesigned.
